DCLK/DOUT aggressor A/B test — 2026-08-17, device msap1 (172.30.19.99)
======================================================================

Bitstream md5 1ac891f9a6e830686dc46749fe238590
MSAP1_PL c1bf5f4 (SCK ratio 32 -> 3.125 MHz), RPU 9dcd385, APU a22f735
Device uptime at test start ~30 min, boot ~14:40 UTC.

HYPOTHESIS
  The AD7771's own DCLK/DOUT conversion-data interface couples into the
  control SPI through the shared 200 mm flying lead, corrupting the address
  field on SDI.

METHOD
  In 4-lane DOUT format the AD7771 clocks 64 bits per lane per frame at a
  fixed DCLK of 8.192 MHz. At 128 kSPS that is 8.192 Mbit/s per lane, i.e.
  the interface is saturated and DCLK is effectively continuous (~100% duty).
  Lowering the output data rate keeps DCLK's frequency at 8.192 MHz but makes
  it bursty, so the aggressor's DUTY CYCLE falls while cable, SCK frequency,
  pin drive and every ADC register stay identical.

  Each arm: 200 forced register-health sweeps via `mnc meter health --refresh`
  (97 register reads per sweep; the plain health path returns the APU cache
  and generates no SPI traffic). Equal wall-clock exposure, 112 s per arm.

  Counters are cumulative since RPU start and were snapshotted immediately
  before and after each arm. The rate change itself performs a reconfigure,
  which generates its own SPI traffic; arm B's opening snapshot was taken
  after that had settled so it is not counted.

                        callbacks 221 (deficit 64), ring 64

  SPI_INVALID_READ_ERR is GEN_ERR_REG_1 bit 3 -- the ADC decoded an INVALID
  REGISTER ADDRESS off SDI. That places the corruption on the outbound path
  and explains the single-bucket histogram: an invalid address means the ADC
  never drives a valid 0010_0000 header, so the received top nibble is always
  zero.


NOTES / CAVEATS
---------------

- The rate changes restart capture, so the DMA transport soak resets
  (produced 285 at test end). Not a fault.
- Ratio is not linear in duty cycle: a ~128x duty reduction gave a 13-24x
  error reduction. Arm B's residual single event in each metric may be a
  floor from another source, or from the periodic 30 s audits running
  alongside the forced sweeps. One event is too few to characterise.
- ROM_CRC_ERR in the sticky latch is unresolved. The sticky OR is itself
  accumulated over the corrupting bus, so an address-corrupted read of 0x59
  could fold in another register's contents as phantom bits. Per-bit counters
  would separate a one-shot power-up event from a recurring fault.
